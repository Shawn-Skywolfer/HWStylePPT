# 会话授权、子进程权限与诊断恢复

## 脑图跨浏览器访问

启动器输出的完整脑图 URL 带 `/#token=...`，浏览器首次载入后存入本标签页 sessionStorage 并从地址栏移除。复制移除凭证后的短地址到其他浏览器，会正常收到 401；不能据此关掉授权检查。

在已有授权页点击“访问链接 / 环境”→“读取完整访问链接”，复制到可信的系统浏览器，或点击“在系统浏览器打开”。若宿主限制启动浏览器，显示原因并手动复制。未授权页面可粘贴同地址、同端口的完整链接重新连接；不同来源链接拒绝处理，避免把凭证传到错误地址。凭证不写入诊断、模型请求或公开日志，不改为长期 localStorage 保存，也不从未授权接口获取令牌。

## EPERM 不等于内容不合法

工作台启动时执行无模型调用的 Node 子进程检查；`GET /api/runtime` 返回是否可以启动子进程，明确浏览器与模型尚未验证。失败时网页显示运行环境说明；生成和自动桥接在创建任务前被拦截，避免重复产生失败任务。Provider 网络请求和手动桥接不被伪装为自动执行。

后台服务通常继承启动它的宿主权限；`detached`、`unref` 或换命令解释器不是权限恢复。若原宿主不允许派生进程，Agent 应向用户解释并请求允许在普通桌面终端重新启动服务；不能自行关闭安全软件、提权、绕过策略或改用另一个 Agent。一般不需要管理员权限。网页中的恢复命令是供用户检查和执行的显式命令，不自动执行。

恢复当前项目时先读取最新状态，确认没有运行/排队任务，备份代码与项目。只停止已核对项目、端口、PID 的工作台，不结束整个 Harness 或其他服务。保留 content-plan.json、current/original/confirmed Markdown、确认快照与历史；重新启动后核对字节哈希、项目 ID 和运行检查。不要自动发起付费模型调用，不将旧失败标成成功。未确认编辑仍需用户确认。

新错误包含 `PROCESS_LAUNCH_DENIED`、实际 phase/executable/systemCode/syscall；进度节流不能丢弃阶段变化。旧 `spawn EPERM` 记录不一定能追溯具体组件，不能事后编造日志。桥接失败后规则选版可有明确降级记录，但 Node/浏览器组件无法启动仍应停止并报告真实原因。

## 诊断按钮

### 保存错误与中文路径锁

EEXIST、PROJECT_BUSY、EPERM 不等于内容或模板不合格。一次实际故障来自特定捆绑 Node 在中文路径下递归删除返回成功但留下保存锁；不能由此断言所有同版本 Node 都有缺陷，也不能把微信收到附件的只读属性当作原项目属性。新版本保存锁仅删除它自己的 owner.json 并显式移除空目录，不递归删除未知内容；活动进程持有的锁仍拒绝并发写入。遇到残留活动锁，先核对 PID、项目与运行状态，不自动杀进程或强删锁。

文件不可覆盖等异常显示 PROJECT_STORAGE_FAILED 和底层 systemCode/syscall/target；默认私有日志为 .private/workbench-errors.jsonl，仅保存阶段和错误元数据，不写令牌、提示词、正文或模型结果。日志最多约 1 MB 后轮换。正文未保存时先保留浏览器编辑或导出草稿，再检查原文件属性/占用情况；不自动取消只读保护、不改 ACL、不提权。必要时由用户同意后备份并换已验证运行时重启。

- “导出诊断记录”请求浏览器下载；若内嵌 WebView 禁止下载，可“查看 / 复制 JSON”，或保存到本项目 `diagnostics/dashi-diagnostics-*.json`。下载被请求不等于已确认文件落盘，界面明确提供替代路径。
- 服务端保存路径由服务生成，不接受任意目标路径；报告只保留白名单字段并脱敏，不包含会话凭证、提示词、模型正文或配置密钥。保留失败阶段和系统代码。
- “清理已处理记录”只清理已标记记录，零条时说明还有多少待处理。“清除全部显示记录”先确认，可撤销本次清理。后台任务/日志、稿件和 PPT 不删除；清理显示不等于执行成功。

## 验证边界

### PPTX 字号比例保真

字号、行距和字距按当前幻灯片实测尺寸与文字累积缩放统一换算成 PPT 点数；不能按中英文或字体名称套用不同系数。Theme17 的 1280×720 内容层放大到 1920×1080 时，文字的 1.5 倍变换也必须计入，SVG 文字则读取屏幕变换。保留 10% 小字号，不再用固定最小值放大它。文字继续为可编辑文本，使用自由调整而非溢出缩字。

服务端和浏览器导出共用同一换算逻辑。已有稿件不必重新策划：先保存备份，更新 Skill 并重启对应预览服务再导出；若走旧 HTML 内嵌的浏览器兜底，需同步新版 editable-pptx-browser.js，不能声称只更新服务就会替换旧内嵌代码。回归核对实际 PPTX 的字号、可编辑文字与渲染图；本机无目标字体或 Office 排版差异仍可能影响断行，不宣称像素级完全一致。

### PDF 候选窗口隔离

服务端截图 PDF 使用 layoutEditor=0 的只读演示页面，不安装任务面板/版式编辑器，不自动弹出或应用待确认候选。截图前关闭导出专用页面中的弹窗，并屏蔽候选/裁切/编辑手柄等界面元素；不是在用户原浏览器中关闭或删除候选。普通编辑页面在导出锁定期间推迟候选弹出与自动应用，解锁后由后续任务刷新继续处理。

PDF 只输出当前已应用、已保存的正式页；未接受候选不应出现为第二层、原稿对比区或遮罩。服务端修复可用于已有 HTML，更新 Skill 后先保存/备份并重启对应预览服务再导出，不需要重新策划内容或整册覆盖生成。旧 HTML 的浏览器内兜底仍应同步新版编辑器保护，再验收；不把服务端回归等同于所有旧版本兜底路径已验证。

真实报告应分别检查中性内容与模板契约、HTML 渲染与逐页溢出、PPTX 导出和环境权限。示例在普通桌面环境成功，不能代表受限 Harness/WebView 一定可用。可在用户授权后复制确认快照做隔离检查，不复制私密宿主配置、不覆盖当前编辑，也不默认调用模型。

命令行导出支持 `node <skill-root>/project/scripts/export-pptx.mjs <ppt目录> <输出.pptx> --report <report.json>`，报告中的 SVG 图片保真回退不等于文字丢失，应分别核对可编辑文字和图形编辑能力。
