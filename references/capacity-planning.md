# 生成前的内容容量匹配与无损分页

## 目的和顺序

先由 Agent 理解、提炼并组织材料，再估算内容与完整主题库的匹配，之后打开脑图。容量估算不把初稿锁在某个模板；确认后仍进行全篇视觉策划和浏览器实测。初稿不应为了六卡模板而删除论据，也不能承诺任何数量或字量都能塞在一页。

`create --mode fine --plan draft.json` 和中性内容 `direct --mode direct` 自动调用规划器。可先执行：

```bash
node <skill-root>/scripts/content-workbench.mjs fit-plan --plan draft.json --out fitted.json
```

输出 report 包含原/新页数、逐页候选、无损拆页去向和待处理原因。`reviewCount > 0` 表示仍需处理，不能宣称全部页面通过。`--out` 只输出规划稿，不覆盖输入文件；此命令不启动浏览器或调用模型。

## 匹配和分页规则

- 先匹配原主题库；必要时尝试注册的自适应版式。新增 `theme17_content_bento` 上限 12 块，按实际全文和来源估算高度，正文不小于 16px（1280×720 设计坐标）；数字上限不是容纳保证。原六块布局契约不放宽。
- 独立、无显式关系的纯文字块，只有没有安全一页候选时才按原顺序分页。每个块的标题、全文、来源、子要点、稳定 ID 和已有元数据完整搬移。页面总论点保留首部分，页面来源在各部分保留；续页标题包含原完整标题与部分编号。完整标题仍超容则停止自动拆分，不截断。
- 原稿保存在 `original` 和 `content-original.md`。初始自动分页作为可撤销的内容事务；撤销/重做不重新调用 AI。`initialPlanning` 记录首次处理。初稿拆分后在脑图中可见，用户逐页微调和确认。
- 每页 `pagination:"single"` 表示必须一页；`brief.pagination:"fixed"` 表示固定总页数。用户有明确要求时必须记录，不得以自动分页覆盖。高密度仍不适合时列为待处理，供用户决定内容重组或显式精炼。
- 单个完整块、图表与解读归属、媒体归属、显式关系或手动自由排布，不能机械截断。保留原页，说明原因，可用既有 AI 精炼/拆页候选审阅。数字、来源和关系不猜测；不能以分页绕过重复内容或数据校验。
- 项目仍最多 60 页。分页后超限时不应用扩页，不删尾页。

## 编辑和确认

脑图常驻“容量匹配 / 分页”入口，编辑后自动刷新估算摘要。窗口列出每页匹配状态、待处理原因、拆页去向及完整块内容，可设置“本页必须一页”、定位节点、重新检查或关闭。

修改后的无损分页始终先预览，再点击确认应用，纳入持久化撤销/重做；未确认不改当前稿。确认内容和点击生成时再次检查，超容或尚有分页候选先回到容量窗口，不启动昂贵的生成流程。后端及 CLI 确认也阻止绕过；正式生成仍执行全部校验。

POST `/api/capacity`：预览 `{action:"preview",revision,contentRevision}` 返回 report，不写文件；应用 `{action:"apply",sourceHash,planHash,revision,contentRevision}` 在重新计算并核对哈希后提交事务。旧预览、编辑冲突、伪造哈希和暂停中的工作台不能应用；原有回环地址、会话令牌及同源限制不变。

## 范围

本轮不新增任意节点角色转换、关系连线编辑器或第三方 ICON 库，不引入远程依赖。生成后的原文换版/AI 适配继续使用确认稿与内容映射；旧 goal-only 演示缺映射时明确提示，不推断归属。
