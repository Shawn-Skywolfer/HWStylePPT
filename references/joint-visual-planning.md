# 内容—视觉联合策划

## 内容初稿之前

完成受众、场合与主要诉求问答后，先运行 `node <skill-root>/scripts/content-workbench.mjs design-catalog`。读取表达家族、使用场景、阅读路径、禁用场景与可用布局；暂停模板不得使用。对关键页的至少两种不同表达方案运行 `constraints --layout <ID>`，读取真实槽位、正文/数据/媒体边界，再组织初稿。不是先写统一的四块内容，再寻找四卡片。

先理解原稿事实和论证，形成“这页要让谁理解/判断什么”，再比较：并列还是先后、主次还是等权、路径对照还是指标对比、图示还是解释型文字。不能为选中漂亮模板，制造原稿没有的日期、数据、因果、主次或截图。需要解释的材料保留机制、证据、案例和边界。不要过度摘要来迁就旧模板。

把选定的表达理由写入 `visualIntent`，明确主要阅读路径、重点、真实数据/素材以及不能误表达的关系；用 `board` 记录实际关系。初稿仍是可编辑的结构化内容，不是把模板 HTML 塞进脑图。

有主次时明确引用已有内容块的名称，例如“抓住关键为主”；不能用数组第一块代替真正重点。聚焦、主辅指标及非对称 HW 版式按明确重点安排主区域，保留原稿文本顺序与稳定内容 ID，不改写来源内容。

`design-catalog --plan draft.json` 与 `fit-plan` 会报告部分明确的“意图与关系冲突”，例如原稿明确禁止先后流程而 board 却带自动顺序线。初稿尚未确认时，由当前 Agent 核对原文修正；有歧义的关系交由用户确认。已有确认稿只提出候选，不能静默改图或覆盖当前控制台。

## 内容确认之后

默认硬性分档：图文并茂＝实际可见业务 ICON ≥3 个 > 其他 ICON＝真实数据图表＝Highlight > 普通文字。先满足事实、素材授权、真实关系、完整解释和容量；在安全组合中先保留第一档页面数，再保留第二档页面数，同档再比较内容适配、HW 和节奏。功能不能累计加分跨档；不能补无关 ICON 凑数，普通卡片/粗体不算 Highlight。用户手选优先。缺少软件截图时只能预留已授权的可替换槽，不伪造截图或自动调用付费服务。图表只用于真实结构化数据。

所有安全候选带 `visual` 描述：表达类型、构图家族、阅读路径、适用/禁用场景、解释密度与素材需求理由。整篇选版比较语义适合度与家族节奏，不以版式 ID 不同冒充视觉不同。HW 是同等适合度下的优先，不设最低页数配额。用户的手选版式保留优先级。

规则评分是可解释的规划估算，不是假称 AI 看过画面。Agent/模型视觉策划可在安全候选中进一步选择，不能只按候选顺序或 HW 页数选择。关系重组、内容改写和拆合页仍走已有可审阅的适配候选与确认流程；单纯重排现有完整块、在等义安全布局间选择，不另加确认。

生成后实测全文、来源、真实数据、连线、备注、溢出与标题基准。需要声称“画面更好”时，提供同一内容、同一比例的真实前后预览，不能用规则得分或模板数量代替视觉验收。
