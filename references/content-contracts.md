# 内容与版式契约

两种模式都在分析材料、编写初稿之前读取本文件。先在 Agent 对话确认需求，再查询适合该内容角色的候选，读取候选的真实约束；不要先写任意数量、任意长度的内容再硬塞模板。

默认按商务咨询、大企业内部汇报/提案策划：标题提炼判断，正文保留解释机制、证据/案例、业务含义与必要边界。提炼是理清结构、去掉重复，不是把完整论证压成孤立关键词或口号。优先选择能承载这些内容的版式；确需精炼/拆页时给出候选并确认，不以留白为由过度删减。用户明确要求极简演讲等其他方式时再调整表达密度。

精细与直出模式的整套生成均要求物理相邻的两页正文使用不同的已登记 layout ID；封面、章节、封底豁免。同一固定 layout 全篇最多使用两次；`theme17_content_*` 与 `theme17_chart_*` 可复用。颜色、字号、槽数和别名不算不同版式。内容、来源、数据和容量优先保持正确；找不到合法不同版式时返回明确的排版组合问题，不静默降低内容完整性。

## 查询每个版式

`node "<skill-root>/scripts/content-workbench.mjs" constraints` 返回全部版式索引；对实际候选执行 `constraints --layout <layout-id>`。这些结果直接读取渲染器的同一份契约，包括字段/数组形状、字数预算、精确变体槽数、数量绑定、表格列长绑定、图片数量、图表数据项和数值范围。`selectable:false` 禁止新选用。不要凭记忆填字段，也不要把最大数组长度当成所有变体的容量。

HW 原稿的 `variants[].cards` 是所选档位的精确正文槽数；图表数据块不算独立解读槽。流程是 3–6 步并独立选择呈现样式，时间线是 3–8 节点。其他模板按查询结果，不硬编码通用“最多 6 个”。字数预算是上限，不是填满目标；原稿几何还会执行空间估算，最终必须通过真实浏览器检查。

## 初稿不可缺的结构

在拆解原稿前执行 `design-catalog`，同时考察原始 71 个版式中的正文、HW 系列和设计感版式，不先锁成同一种卡片。目录只能承载标题；大号数值位不能承载段落；图表必须有真实数据。多区域版式须先明确业务分区：例如方法论的 `layers` 与 `steps`、双区域策略的 `steps/cards`、阶段叙事的 `nodes/metrics`。对这些模板，内容块用 `origin.presentation:{layout:"目标ID",region:"区域key"}` 声明归属；该字段只是分区，不改变原文或授权改变关系。不能按块数平均分区、复制内容补槽。已有确认稿若缺少分区，通过控制台 AI 适配候选审阅，不静默回写脑图。

原始模板的正文容量由专用字段契约提供，不再只按示例短句推算；查询到的字符上限仍须经过实际浏览器溢出检查，不能据此承诺任意正文都放得下。来源区可合并完全相同的来源字符串，不增加重复的程序归属标签；每条不同的完整来源仍须可见，不以简称或隐藏属性代替。

- `slide.title` 是非空的页面论点，显式填写 `role`。`cover / chapter / section / transition` 的 `blocks` 必须为空；封面摘要写 `conclusion`，正文另起页。不能把含正文的第一页默认为封面。
- 每个 `block.label` 必须为准确的非空标题，即使它下面已经有正文/子要点/数据。不能用空标题包裹内容。子要点 `contentTree.children[]` 的 `text` 也不得为空；仅正文根包装节点可为空并承载有标题的子要点。
- 正文 `text`、来源 `evidence`、结构化 `data` 分开保存。稳定 ID 唯一，关系端点必须有效。不要把来源塞进正文槽或复制数字来填槽。
- 图表必须提供匹配的 `labels / values`、真实有限数值、单位；占比合计、负值支持、固定维度、最小/最大项数按 `dataSeries`，不能补零、取绝对值或伪造数据。媒体路径和数量按查询契约。
- 一页放不下时完整拆分原子内容块；保留全部事实、子内容、数字、来源和显式关系。单个长块无法容纳时，在打开脑图前向用户展示拆分/精炼方案；不能截断或者只留前几个节点。用户要求固定页数/单页时先审阅方案，不擅自拆页。

## 生成前验证

草稿完成后执行 `fit-plan --plan <draft.json>`，检查每页 `status`：`matched / fixed` 可继续，`split` 审阅无损分页，`review` 先解决 `error.code / issues`。新建入口拒绝空标题及封面正文冲突，不创建损坏的初始项目；旧项目仍可打开并修复，编辑中的临时空节点可保存，但不能确认或生成。不要用通用“待补充”冒充已完成分析。

精细模式初稿同样执行全篇内容—视觉联合匹配。报告 `visualPlanning` 保存同一套分档、相邻不同版式与逐页推荐；`options[].visual` 保留实际ICON数、媒体授权及优先档位。推荐不改正文、不锁定版式。编辑后或确认前按最新稿重新匹配，不能沿用过期候选或把“每页单独放得下”误认为全篇可生成。

用户确认后的阶段仍统一匹配完整主题库，而不是锁死初稿候选。适配必须保持已确认原意、数字和来源；必要改写先提供可视候选确认。字段检查、规划容量检查、浏览器完整性/溢出检查是三层独立检查，不能用其中一层代替其他层。

执行 `usage-report --plan <draft.json> --out <report.json>` 查看逐模板的选用、可直接适配、需内容适配及不适用原因；生成目录也保存 `layout-utilization.json`。固定封面、章节和封底不参与利用率。控制台“模板利用”按当前页保存状态重新核对，不以最初脑图覆盖当前编辑。可用但未选不等于失败，缺少真实数据也不应为了覆盖率而伪造。两种工作模式使用同一完整候选和整套节奏规则，优先级内比较正文适合度、构图家族与重复次数，不随机凑模板数量。

## 运行故障不等于内容故障

换版的关系兼容性同时核对模式、内容块数量、真实连线及多区域分组；单块探测没有连线，不证明它能保留多步流程。需要改变关系呈现时，先显示来源关系与目标分组并取得明确授权，再调用模型。模型意外改关系时，在原有最多两轮预算内要求恢复，不自动扩大授权；仍无法通过则提供“查看并确认关系调整”入口。用户确认只允许生成新候选，仍须校验数字、来源、原块去向及每条关系的可见表达，并在真实版式预览中再次确认后才应用。不得把确认按钮作为删除原意或绕过关系检查的开关。

多区域容量直接从渲染契约计算：例如 page066 为 nodes 2–4 加 metrics 2–4，总计4–8块，不是任一数组的2–4块。AI收到区域key、用途、字段与每区上下限，每块用 origin.presentation:{layout,region} 明确归属。不能通过单数组适配器隐藏其他必需区域；已映射区域须显式显示。第一次失败后将上一完整候选和逐字段问题送入第二轮修订，仍保持两轮预算、用户授权及完整页面验收；不把重复缩短文字当作区域结构修复，不自动按数量切分业务含义。

真实页面检查必须同时核对跨区域碰撞、文字互叠和被不相关的实色卡片遮挡，不能仅凭DOM中仍有文本就宣称完整。碰撞返回具体组件/字段位置，纳入现有有界AI修订；应用继承用户样式后再检查一次，失败恢复当前页。方法版式右侧卡片的构图不变，左侧解释在既定列内换行；图表根据说明行数为数值标签留空，保留数据与相对比例。旧图表修复只调整必要的几何留空，不替换文字、编辑标识或数据。

控制台通过 `/api/layout-runtime` 核对正在运行的服务协议，不以磁盘上的包版本代表已加载的后端。页面与服务不兼容时，在模型调用前停止并要求刷新或重启。当前页面由本会话发起的关系错误自动打开一次确认窗口；其他页任务及历史记录保留显式入口，不反复弹窗，不自动重发付费请求。

AI换版及失败恢复共用单层选项界面：用户选择“按新版式整理”或“精简重复内容”，无需自己编写提示词。必要的关系/表格授权仍须明确确认。点击“生成候选”后立即反馈提交状态并禁用重复提交，取得任务后展示阶段、真实等待时间、暂停/取消和后台运行；候选完成后先预览，再确认应用。错误默认使用业务语言，原始代码与模型诊断留在LOG；配置参数和核对细节折叠，不堆叠常驻教学段落。选择处理方式、关闭窗口和取消不自动重发模型请求；继续执行已暂停任务须提示可能重新计费。不能把任何方案理解为删除原意、改数值或立即覆盖页面的许可。

候选生成后以当前保存页核对编辑冲突。缓存 ID、renderSlot 和空样式默认值不参与编辑指纹；文字、数据、图片显示/素材和非空样式变化必须参与。冲突提供“保留当前页”与“替换改动并应用”，替换须明确确认，使用现有已校验候选，不重新调用模型。确认替换前重新核对状态，保存最新页作撤销快照；等待中再次编辑不得静默覆盖。应用阶段显示进度并防止重复提交，失败保留原页和候选，允许重新审阅，不强迫回脑图或重生候选。

`PROJECT_STORAGE_FAILED` 是保存问题；`RENDER_BROWSER_CRASH / RENDER_BROWSER_UNAVAILABLE` 是浏览器校验中断；`WORKBENCH_CONNECTION_LOST` 是服务连接中断。不要据此删正文、强制换模式或重复调用模型。暂停/取消先中止当前执行，再保存状态；文件占用时明确显示尚未持久保存。继续从安全阶段重新运行，不声称断点续传。
